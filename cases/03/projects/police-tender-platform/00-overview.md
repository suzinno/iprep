# Tender Platform for a MENA Police Department — System Design Overview

A government-to-business tendering platform with an embedded vendor CRM, carrying a police department's procurement from drafting a requirement pack through sealed vendor submission, committee evaluation and award. The architecture is organised around one problem that is genuinely hard and one that is not: a sealed bid must be provably confidential until the deadline and provably unaltered afterwards, and a third-party language model must be useful over classified procurement documents without ever being able to influence an outcome — while raw throughput, at a modelled 70 [QPS](https://en.wikipedia.org/wiki/Queries_per_second "Queries Per Second — Throughput measure of how many requests a system serves each second") ordinary peak, is unremarkable. The resolution is **[PostgreSQL](https://www.postgresql.org/docs/current/ "PostgreSQL — Relational database storing and querying structured data with strong transactional guarantees") as the only store that decides anything, an append-only hash-chained submission ledger mirrored to Object Lock storage, per-bid envelope encryption whose key grant is created only at unsealing, and an [AI](https://en.wikipedia.org/wiki/Artificial_intelligence "Artificial Intelligence — Software that generates or assists with tasks such as writing code") layer that is advisory by construction** — every generated claim resolves to a page of a real document or the artifact is discarded. Eight [FastAPI](https://fastapi.tiangolo.com/ "FastAPI — Python web framework for building HTTP APIs with async support and automatic schema generation") services on EKS keep bid custody, evaluation and model egress in separate blast radii; bytes reach S3 by presigned upload and never traverse the [API](https://en.wikipedia.org/wiki/API "Application Programming Interface — Defines the contract by which software components exchange requests and data"), which is what makes a 10× deadline surge a non-event.

## Technology Stack and Roles

| Technology | Role |
|---|---|
| **Python / FastAPI** | All eight services and four [Celery](https://docs.celeryq.dev/en/stable/ "Celery — Distributed task queue that runs background and scheduled jobs outside the request cycle") worker deployments; async handling for an almost entirely I/O-bound workload |
| **[Pydantic](https://docs.pydantic.dev/latest/ "Pydantic — Python library that validates and parses data against typed models at runtime")** | Request/response contracts, [OpenAPI](https://www.openapis.org/ "OpenAPI Specification — Describes an HTTP API's endpoints, schemas and behavior in a machine readable format") generation, settings validation at startup, and strict validation of model output before any artifact is stored |
| **[SQLAlchemy](https://www.sqlalchemy.org/ "SQLAlchemy — Python SQL toolkit and ORM that maps objects to relational tables and builds queries")** | [ORM](https://en.wikipedia.org/wiki/Object%E2%80%93relational_mapping "Object Relational Mapper — Maps application objects to relational database rows and queries") for domain writes; Core for reporting and search-adjacent queries where the plan matters |
| **[Alembic](https://alembic.sqlalchemy.org/en/latest/ "Alembic — Applies and versions database schema migrations for SQLAlchemy")** | Migration history, expand/contract only, run as a pre-deploy Job so rollback never faces a narrowed schema |
| **Celery** | Worker runtime for `celery-documents`, `celery-scoring`, `celery-imports` (brokered by `redis-broker`) and `celery-ai` (brokered by `sq-ai-jobs`, for its visibility timeout and DLQ) |
| **LangChain** | Document loaders, splitters, embedding and retrieval plumbing for extraction and summarization |
| **LangGraph** | The pipeline itself — checkpointed multi-step runs with validation and retry branches, so a rate-limited job resumes instead of restarting |
| **OpenAI API** | Embeddings for the vector index, map-stage chunk summarization, reduce-stage report composition — reached only through the egress-controlled subnet |
| **PostgreSQL** (`postgres-core`, RDS Multi-AZ + 1 read replica) | System of record: tenders, versions, criteria, vendors, CRM, bids, manifests, the submission ledger, scores, awards, the AI citation index, and partitioned audit |
| **[Redis](https://redis.io/docs/latest/ "Redis — In-memory data store used as a cache and fast key-value store")** (`redis-cache`) | Listings, vendor records, [JWKS](https://datatracker.ietf.org/doc/html/rfc7517 "JSON Web Key Set — Publishes the public keys a party needs to verify a signed token"), rate-limit counters, idempotency keys, query embeddings, AI map-stage results — cache-aside and entirely expendable |
| **Redis** (`redis-broker`) | Celery transport, a separate instance so a task backlog cannot evict the cache |
| **Amazon OpenSearch** (`opensearch-corpus`) | Domain search: [BM25](https://en.wikipedia.org/wiki/Okapi_BM25 "Best Matching 25 — Ranking function that scores how relevant a document is to a search query") over extracted text plus 768-dimension `knn_vector` semantic retrieval, and the aggregation source for tender analytics |
| **Elasticsearch / Logstash / Kibana** (`es-logs`) | Operational log analytics only, on a separate cluster so a log flood cannot degrade tender search during the same incident |
| **[Kafka](https://kafka.apache.org/documentation/ "Apache Kafka — Distributed log that stores partitioned, replicated streams of records for publish-subscribe and stream processing") (Amazon MSK)** | Ordered, replayable domain event log feeding the search projection, notifications and the immutable audit sink |
| **AWS SQS** | Point-to-point command delivery with visibility timeouts and DLQs: `sq-document-intake`, `sq-ai-jobs`, `sq-notification-dispatch` |
| **AWS Lambda** | `fn-object-intake` (S3 `ObjectCreated` validation and metadata extraction) and `fn-notify-dispatch` (SQS-triggered delivery) |
| **AWS S3** | `s3-documents` (requirement and bid packs, extracted text, the Object Lock audit sink), `s3-artifacts` (AI outputs), `s3-tfstate` |
| **AWS Cognito** | `cognito-staff` SAML-federated to the department [IdP](https://en.wikipedia.org/wiki/Identity_provider "Identity Provider — Service that authenticates users and issues identity assertions to relying applications"); `cognito-vendors` for external users with mandatory [MFA](https://en.wikipedia.org/wiki/Multi-factor_authentication "Multi Factor Authentication — Requires more than one form of evidence to verify a user's identity") on submitters |
| **AWS API Gateway** (`apigw-edge`) | Edge routing, JWT authorizer, per-stage throttling and usage plans |
| **AWS IAM** | Service-to-service authorization via IRSA — each deployment's role names only the S3 prefixes, queues, KMS grants and secrets it needs |
| **AWS Secrets Manager** | Model API key, database credentials with rotation, SAML signing material, mesh and mail-relay credentials |
| **AWS VPC** | Private subnets for every workload and data store; one egress-controlled subnet is the sole route to the model endpoint |
| **AWS RDS** | Managed PostgreSQL, Multi-AZ failover, 35-day [PITR](https://www.postgresql.org/docs/current/continuous-archiving.html "Point in Time Recovery — Restores a database to a specific past moment using base backups and archived logs"), snapshots copied to a separate account |
| **AWS Route 53** | Public zone, health-checked records, and ACM certificate validation for the [TLS](https://datatracker.ietf.org/doc/html/rfc8446 "Transport Layer Security — Encrypts and authenticates data sent over a network connection") terminating at CloudFront and the ALB |
| **Docker / Docker Compose** | Image build; Compose reproduces Postgres, Redis, OpenSearch, LocalStack and a recorded model stub for local development and [CI](https://en.wikipedia.org/wiki/Continuous_integration "Continuous Integration — Automatically builds and tests code on every change") integration tests |
| **[Kubernetes](https://kubernetes.io/ "Kubernetes — Automates deployment, scaling and management of containerized applications") / EKS** | Runtime for twelve deployments; [HPA](https://kubernetes.io/docs/tasks/run-application/horizontal-pod-autoscale/ "Horizontal Pod Autoscaler — Automatically adjusts the number of Kubernetes pod replicas to match load") on CPU for services, on `sq-ai-jobs` depth for `celery-ai` and on broker queue length for the other workers; `dev`/`staging` as namespaces, `prod` as a separate cluster in a separate account |
| **Amazon ECR** | Image registry with scan-on-push; the only registry the cluster may pull from |
| **Terraform** | Every AWS resource, state in `s3-tfstate` with DynamoDB locking, applied only from CI, drift-checked nightly |
| **GitHub / GitHub Actions** | Source of truth and the only path to production; [OIDC](https://openid.net/developers/how-connect-works/ "OpenID Connect — Identity layer on top of OAuth 2.0 for authenticating users") federation to AWS so no long-lived deploy credential exists |
| **Bash** | Migration and deploy wrappers, the local development entry point, and the operational scripts CI invokes |
| **CloudFront + AWS [WAF](https://owasp.org/www-community/Web_Application_Firewall "Web Application Firewall — Filters and blocks malicious HTTP traffic before it reaches an application")** | *Addition beyond the brief's stack* — TLS termination, notice-board caching, managed [OWASP](https://owasp.org/ "Open Worldwide Application Security Project — Community effort publishing practices and tools for building secure software") rules, [L7](https://en.wikipedia.org/wiki/OSI_model "Layer 7 — The application layer of the OSI model, where content-aware filtering such as a web application firewall operates") absorption |
| **AWS KMS** | *Addition beyond the brief's stack* — `kms-bid-custody` for per-bid envelope encryption with grant-based release, `kms-data` for general encryption |
| **ClamAV** | *Addition beyond the brief's stack* — upload scanning in `celery-documents`; untrusted vendor uploads are the widest attack surface and the named stack has no scanner |
| **AWS X-Ray / CloudWatch / DynamoDB** | *Additions beyond the brief's stack* — trace backend, metrics and alarms, and Terraform state locking |
